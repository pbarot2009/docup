DocUP

DocUP is a compiler. It reads a .du file and writes a single HTML5 document. The format is block-based: every top-level construct is a named block with optional attributes and a body. This book is written in that format.

Compiler version: 0.2.0.

What it does

A .du file is source. The compiler lexes it, parses it into an AST, checks semantic rules, then emits HTML. Watch mode rebuilds on change and serves the result on localhost.

Output is a complete page: doctype, metadata, CSS, optional KaTeX, and the body. You can inject extra CSS with --style or with a stylesheet field in meta.

Pipeline

  1. Read the input file.
  2. Lex and parse into a document node.
  3. Resolve include statements, recursively.
  4. Run semantic checks.
  5. Generate HTML and write the output file.

What this book covers

Syntax for every block and inline the compiler accepts, the CLI, include resolution, and the checks that run after parse. Features that exist only as ignored attribute keys are not documented as if they did something.

Command line

The binary is named docup. Commands:

usage
text 
docup build <input.du> [flags]docup watch <input.du> [flags]docup versiondocup help

docup -v and docup --version print the same version string as docup version. docup -h and docup --help print usage. Any other command name is an error.

Flags

Flag Meaning
-o, --output Output HTML path. Default is the input path with the extension changed to .html.
-s, --style Path to a CSS file. Its contents are copied into a style tag in the output.
-p, --port Port for the watch-mode server. Default 8080. Must be a valid u16.
-V, --verbose Print elapsed time for each build stage.
-q, --quiet Hide stage progress and the success summary.

--verbose and --quiet together are an error. A flag that expects a value and does not get one is an error. Unknown flags are an error. Only one input path is accepted.

build

Compiles once and writes the HTML file. A missing or unreadable input file is a fatal error. An empty file (only ASCII whitespace) is a fatal error. If the input does not use a .du extension, the compiler prints a warning and continues.

text 
docup build report.du
docup build report.du -o dist/index.html -s style.css
docup build report.du --verbose

watch

Compiles once, writes the output file, then binds 127.0.0.1:<port>. It polls watched files every 250 ms. On change it rebuilds. A failed rebuild leaves the last good (or last error placeholder) page in place and keeps watching.

The served HTML has a small EventSource script injected before </body>. The server also exposes /docup-events and static files from the input file's directory.

text 
docup watch report.du
docup watch report.du --port 3000

Watched paths are the root source file, every successfully resolved include, and the --style file if one was given.

Source layout

A document is a sequence of top-level blocks. The first token of each block is an identifier: the block type. After the last block the file ends. Anything else at top level is a parse error.

Allowed top-level names:

  • meta
  • h
  • p
  • codeblock
  • hr
  • list
  • quote
  • image
  • table
  • callout
  • raw
  • math
  • toc
  • footnote
  • include

Comments

Line comments start with // and run to the end of the line. Block comments are /* ... */ and may span lines. An unclosed block comment is a lex error. Comments are skipped in the token stream. They are not skipped inside raw scopes, inline code, or inline math.

comments.du
text 
// a whole line

p { visible /* hidden */ text }

Strings and numbers

String literals use double quotes. The only escape is a backslash before a quote: \" inserts a quote. An unclosed string is a lex error.

Bare integers are tokens. Heading level is the only place the grammar requires a number.

Whitespace in prose

Inside paragraph-like bodies, runs of space, tab, CR, and LF collapse to a single space. Leading and trailing spaces on a body are trimmed. Line breaks in source do not become line breaks in HTML unless you use a codeblock, raw block, or explicit HTML.

Raw scopes

codeblock, raw, and math take a body that starts with brace-bang and ends at the first bang-brace in the file from that point. The body is not tokenized. A leading all-whitespace line is dropped. Trailing spaces and newlines are dropped.

Attribute lists

Many blocks take a parenthesized list after the name:

text 
name(key: "value", flag: true, "positional")

A named field is an identifier, a colon, then a string or the identifiers true / false. A bare string is a positional argument. Entries may be separated by commas. An empty () is valid where the list is optional.

Which keys are read depends on the block. Unknown keys are stored or dropped; they do not fail the parse.

meta

Optional. At most one per document. If present it must contain title.[1]

meta.du
text 
meta {
  title: "Required when meta is present",
  lang: "en",
  theme: "light",
  author: "Name",
  version: "0.2.0",
  description: "One-line summary",
  keywords: "comma, separated",
  canonical: "https://example.com/page",
  image: "https://example.com/og.png",
  stylesheet: "extra.css"
}

Keys the generator uses:

Key Effect
title Document title and Open Graph / Twitter title. Required if meta exists.
lang lang attribute on <html>. Default en.
theme data-theme on <html>. Use light or dark to lock the palette. If omitted, CSS follows prefers-color-scheme.
author, version <meta name> tags.
description description, og:description, twitter:description.
keywords <meta name="keywords">.
canonical canonical link and og:url.
image og:image and twitter:image.
stylesheet Extra <link rel="stylesheet"> in head.

Values are strings. A second meta block is a parse error. Other keys are kept in the AST and ignored by the generator.

Blocks

h

Heading. Level is a number in parentheses and must be 1 through 6. The body is prose.

text 
h(1) { Title }
h(2, id: "install", class: "section") { Install }

Optional attributes after the level are name/string pairs. The generator writes id and class. If you omit id, the generator builds one from the heading text (lowercase, ASCII letters and digits, hyphens). Duplicate slugs get a numeric suffix.

p

A paragraph. Body is prose: text plus inline elements.

text 
p { One paragraph. Use another p block for the next one. }

hr

Horizontal rule. Empty body.

text 
hr {}

toc

Table of contents. Empty body. The generator fills it from every heading in the finished document, after includes are resolved. Headings are listed in source order with links to their ids. If there are no headings, the block emits nothing.

text 
toc {}

raw

Unescaped HTML. The body is a raw scope opened by brace-bang and closed by bang-brace. A leading blank line of only spaces is stripped. Trailing whitespace is stripped. Empty content after that trim is a semantic error.

Header line:

text 
raw

Then a raw scope whose body is HTML. Nothing inside that scope is lexed as DocUP. Braces and comments are literal. A raw scope ends at the first bang-brace, so a sample inside another raw scope cannot contain that closer.

Inlines

Inlines appear in prose bodies: headings, paragraphs, callouts, table cells, footnote definitions, and the text parts of list items and quotes.

Brace forms: b, i, strike, code, m. Parenthesis forms: link, fn.

Emphasis

text 
p { b{bold} i{italic} strike{struck} }

These nest. Depth is capped at 64; deeper input is a parse error.

Rendered: bold italic struck. Combined: bold italic.

Inline code

code{...} reads bytes until the matching closing brace. Nested braces are counted. There are no inlines inside it.

text 
p { Use code{h(1) { Title }} at the top of a page. }

HTML special characters in the body are escaped in output.

Links

text 
p { See link("https://example.com") { the site }. }

The URL is a string inside parentheses. The visible text is the brace body. An empty URL is a semantic error. Extra comma-separated string attributes after the URL are parsed and discarded.

Example: example.com.

Inline math and footnotes

Inline math uses m{...} and is described with math blocks. Footnote references use fn(id) and are described with footnote blocks.

An identifier that looks like an inline but is not one of the names above is ordinary text.

Lists

A list contains item and task children only. Zero items is a semantic error.

text 
list {
  item { First }
  item { Second }
}

list(ordered: true) {
  item { Step one }
  item { Step two }
}

ordered: true emits <ol>. Anything else, including omitting the attribute, emits <ul>.

Tasks

text 
list {
  task(done: false) { Open work }
  task(done: true) { Finished work }
}

done is a boolean. Missing done is treated as false. The checkbox is rendered disabled.

Nested lists

A list may appear inside an item. It must be the last child of that item.[2]

      item { Child }
      item { Other child }
    }
  }
  item { Sibling of the parent }
}

Quotes

A block quote. Body is prose and, optionally, one nested quote at the end.

text 
quote {
  Outer line.
  quote {
    Inner line.
  }
}

Live example:

A quote is a block, not an inline. Consecutive text inside it becomes one paragraph in HTML.

The inner quote closes the outer body. Do not put text after it.

codeblock

Fenced source. The body is a raw scope opened by brace-bang and closed by bang-brace.

text 
codeblock(lang: "rust", file: "main.rs", line_numbers: true, highlight: "1,3-5")

Follow the attribute list with a raw scope. The live block below is the same construct.

Attributes:

Key Type Effect
lang string Language label and highlight grammar. Empty means no language class.
file string Label in the header.
line_numbers boolean Show line numbers. Default false.
highlight string Line numbers to mark. Comma-separated items, each a number or an inclusive range start-end.

Content empty after trim is a semantic error. The output header always includes a Copy button.

Math

Two forms. Both need KaTeX at runtime. The generator adds the KaTeX tags only if the document contains at least one math node.

Display

Header line is math, then a raw scope of LaTeX. Empty content is a semantic error. Output is wrapped as display math.

\[ \int_{0}^{1} x \, dx = \frac{1}{2} \]

Inline

m{...} is a raw brace body, same rules as inline code.

text 
p { The area is m{\frac{1}{2}}. }

The area is \(\frac{1}{2}\). Einstein: \(E = mc^2\).

Tables

A table is rows. A row is cells. A cell body is prose.

text 
table {
  row(header: true) {
    cell { Name }
    cell { Kind }
  }
  row {
    cell { code{p} }
    cell { block }
  }
  row {
    cell { code{b} }
    cell { inline }
  }
}

Rules checked after parse:

  • At least one row.
  • Each row has at least one cell.
  • Every row has the same number of cells.

row(header: true) emits <th> instead of <td>. Table-level attributes are parsed and ignored.

Images

No body. First argument is the source URL or path. Optional alt is a string. Other named attributes after that are parsed and ignored.

text 
image("images/logo.svg", alt: "DocUP")

An empty source is a semantic error. In watch mode the server maps request paths onto files next to the root input.

Callouts

Admonition block. Body is prose.

text 
callout { Defaults to note. }
callout(type: "warning") { Check the heading level. }

type is a string. Matching is case-insensitive.

type Also accepted
note info
tip hint
warning caution
danger error

Any other string is a parse error. Omitted type is note.

Note
Semantic errors are reported with file, line, and column. The compiler prints the source line and a caret.
Tip
Put examples in codeblock raw scopes so the sample is not parsed as DocUP.
Warning
Heading levels outside 1 through 6 fail semantic analysis, not parsing. The tokens are valid; the values are not.
Danger
include cycles and missing include files fail before semantic analysis. The error is reported against the include statement.

Footnotes

A definition is a top-level block. A reference is an inline.

text 
p { See the rule.fn(required-title) }

footnote(id: "required-title") { Title is required when meta is present. }

The definition needs a non-empty id attribute. The body is prose.

The reference is fn(id) or fn("id"). The identifier form allows letters, digits, underscore, and hyphen.

Checks:

  • Duplicate definition ids are a semantic error.
  • A reference whose id has no definition is a semantic error.
  • Definitions with no references still appear in the footnotes section.

Numbering follows first-reference order in the document after includes are merged. Output ids are fn-<id> and fnref-<id>.

This page uses three definitions. The first two are referenced from earlier sections.[3]

Includes

Splice another .du file into the current document. Two spellings:

text 
include "path/to/file.du"
include("path/to/file.du")

The path is relative to the file that contains the statement, not to the process working directory.

Resolution:

  1. Join the path to the parent file's directory.
  2. Canonicalize. Failure is an error on the include statement.
  3. Reject the path if it is already on the current include stack (cycle).
  4. Read, lex, parse the child.
  5. Resolve includes inside the child.
  6. Append the child's blocks to the parent. Child meta is discarded.[3]
  7. Pop the child from the stack so the same file may be included from a different branch.

An empty path is a semantic error if the statement survives until analysis. In practice a missing file fails earlier.

Watch mode adds every successfully resolved include to the watch set.

This book is one HTML file built from several .du files. index.du holds meta, the title, the toc, the includes, and the footnote definitions.

Semantic checks

Analysis runs on the document after includes are expanded. The first violation stops the build.

Check When it fires
meta title meta is present and has no title field
heading level level is not in 1..6
empty codeblock / raw / math trimmed content is empty
empty list no items
empty table no rows
empty row no cells
ragged table a row's cell count differs from the first row
image src source string is empty
link URL URL string is empty
include path path is empty or only whitespace
footnote id duplicate definition, or a reference with no definition

Parse errors are separate: unknown block names, missing braces, bad callout types, unclosed raw scopes, unclosed strings, unclosed comments, inline or list nesting past 64, text after a nested list or nested quote.

Diagnostics

Errors print the message, then path:line:col, then the source line and a caret. Line and column are 1-based.

Raw

Limits

  • One meta block.
  • Include cycles are rejected.
  • Inline, list, and quote nesting stop at 64.
  • Nested list or quote must be the last child of its parent body.
  • No block inside a paragraph. A list inside p { ... } is plain text.
  • Child-file meta is not merged.

Building these pages

The root file is index.du. From the docs directory:

text 
docup build index.du
docup build index.du -o index.html
docup watch index.du --port 8080

Output defaults to index.html next to the input.

  1. If a document contains a meta block, that block must include a title field. A document with no meta block is valid; the generated page title then defaults to "DocUP Document". ↩
  2. After a nested list is parsed inside an item, the item must close. Text after that nested list is a parse error. The same rule applies to a nested quote inside a quote. ↩
  3. An included file may contain its own meta block. The compiler parses it, then drops it. Only the included file's blocks are spliced into the parent. ↩
