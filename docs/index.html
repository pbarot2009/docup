DocUP

DocUP is a compiler. It reads a .du file and writes a single HTML5 document. The format is block-based: every top-level construct is a named block with optional attributes and a body. This document is written in that format.

Compiler version 0.2.0.

1. Overview

A .du file is source. The compiler lexes it, parses it into an AST, checks semantic rules, then emits HTML. Watch mode rebuilds on change and serves the result on localhost. docup fmt rewrites source. docup new and docup init write a starter project.

Extra CSS can be injected with --style or with a stylesheet field in meta. Those two paths are not the same. See section 1.3.

1.1 Pipeline

  1. Read the input file.
  2. Lex and parse into a document node.
  3. Resolve include statements, recursively.
  4. Run semantic checks.
  5. Generate HTML and write the output file.

1.2 Scope

This document covers every block and inline the compiler accepts, the CLI, themes, highlighting languages, include resolution, and the checks that run after parse. Keys that are parsed and then ignored are named as ignored.

1.3 Generated page

The output is a complete HTML5 document. The generator always writes:

  • <!DOCTYPE html> and <html lang="...">
  • charset and viewport meta tags
  • title, Open Graph, and Twitter tags derived from meta
  • a generator meta tag using the compiler version
  • font links chosen by the theme
  • page CSS: font variables, the theme palette, base rules, and any theme-specific rules
  • a copy-to-clipboard script for code blocks

Added only when needed:

  • KaTeX CSS and scripts, if the document contains any math node
  • a <link rel="stylesheet"> from meta field stylesheet
  • a <style id="docup-custom-css"> block from --style
  • data-theme on <html>, from meta field theme

Theme names and light/dark locking are section 4.1.

2. Command line

The binary is named docup. Commands:

usage
text 
docup build <input.du> [flags]docup watch <input.du> [flags]docup fmt [path] [--check] [--stdout]docup new <directory> [flags]docup init [flags]docup versiondocup help

With no command, the compiler prints help and exits 1. docup -v, docup --version, and docup version print the version string. docup -h, docup --help, and docup help print usage.

Color in the terminal is on when stdout is a terminal and NO_COLOR is unset. Otherwise ANSI codes are omitted.

2.1 Shared flags

Used by build and watch:

Flag Meaning
-o, --output Output HTML path. Default is the input path with the extension changed to .html. If the input has no extension, .html is appended.
-s, --style Path to a CSS file. Contents are copied into <style id="docup-custom-css">.
-p, --port Watch-mode port only. Default 8080.
-v, --verbose Print elapsed time for each build stage. On build and watch, -V is accepted as an alias for -v.
-q, --quiet Hide stage progress and the success summary.

--verbose and --quiet cannot be used together.

2.2 build

Compiles once and writes the HTML file. A missing or unreadable input file is a fatal error. An empty file (only ASCII whitespace) is a fatal error. If the input does not use a .du extension, the compiler prints a warning and continues.

text 
docup build report.du
docup build report.du -o dist/index.html -s style.css
docup build report.du --verbose

2.3 watch

Compiles once, writes the output file, then binds 127.0.0.1:<port>. It polls watched files every 250 ms. On change it rebuilds. A failed rebuild leaves the last page in place and keeps watching.

If the first compile fails, the server still starts. The page body is a short HTML error placeholder until a later compile succeeds.

text 
docup watch report.du
docup watch report.du --port 3000

Watched paths are the root source file, every successfully resolved include, and the --style file if one was given.

2.4 Dev server

The watch server accepts GET only. Other methods return 405.

Path Response
/, /index.html Current compiled HTML, with a live-reload EventSource script inserted before </body>.
/docup-events Server-sent events. A rebuild writes data: reload.
any other path File under the input file's directory, if it exists. Otherwise 404.

Asset Content-Type is chosen from the file extension: html, css, js, json, png, jpg, jpeg, gif, svg, webp, ico, woff, woff2, ttf. Anything else is application/octet-stream.

2.5 fmt

Parses a .du file and writes it back in canonical form. Default path is the current directory.

text 
docup fmt
docup fmt docs
docup fmt index.du
docup fmt --check
docup fmt index.du --stdout
  • With no flags, files that differ are rewritten.
  • --check prints paths that need formatting and exits 1 if any do. Nothing is written.
  • --stdout prints one formatted file to stdout. It cannot be used on a directory.
  • --check and --stdout cannot be used together.

Directory walks skip hidden names and the folders target, node_modules, and dist. Only files with a .du extension are formatted.

Canonical form: four-space indent, meta keys in a fixed order then alphabetical leftovers, blank line between top-level blocks, prose wrapped near 80 columns. fmt parses first; a parse error is reported and that file is skipped.

2.6 new

Creates a directory and writes a starter project. The directory must not exist, or must be empty.

text 
docup new my-doc
docup new my-doc --title "Report" --author "Name" --theme textbook --desc "Notes" -y

Flags: --title, --author, --theme, --desc, and -y / --yes to skip prompts. Without --yes, and when stdin and stdout are terminals, the command asks for title, author, theme, description, and whether to include sample sections.

2.7 init

Same files as new, written into the current directory. Aborts if index.du already exists.

text 
docup init
docup init --theme nord -y

Files written when missing: index.du, style.css, .gitignore, README.md. Theme names accepted by these commands: textbook, default, sepia, nord, solarized. An unknown theme falls back to textbook.

3. Source layout

A document is a sequence of top-level blocks. The first token of each block is an identifier: the block type. After the last block the file ends. Anything else at top level is a parse error.

Allowed top-level names:

  • meta
  • h
  • p
  • codeblock
  • hr
  • list
  • quote
  • image
  • table
  • callout
  • raw
  • math
  • toc
  • footnote
  • include

3.1 Comments

Line comments start with // and run to the end of the line. Block comments are /* ... */ and may span lines. An unclosed block comment is a lex error. Comments are skipped in the token stream. They are not skipped inside raw scopes, inline code, or inline math.

comments.du
text 
// a whole line

p { visible /* hidden */ text }

3.2 Strings and numbers

String literals use double quotes. An unclosed string is a lex error. Escapes inside strings:

Sequence Result
backslash quote a quote
two backslashes a backslash
backslash n newline
backslash t tab
backslash r CR

Any other character after a backslash is kept as that backslash plus the character.

Bare integers are tokens. Heading level is the only place the grammar requires a number.

3.3 Identifiers

An identifier starts with an ASCII letter or underscore. Later characters may be letters, digits, or underscore.

In two raw contexts the scanner also accepts hyphen: footnote ids written without quotes, and attribute names inside link parentheses. Quoted footnote ids may contain any string bytes.

3.4 Whitespace

Inside paragraph-like bodies, runs of space, tab, CR, and LF collapse to a single space. Leading and trailing spaces on a body are trimmed. Line breaks in source do not become line breaks in HTML unless you use a codeblock, a raw block, or explicit HTML.

3.5 Raw scopes

codeblock, raw, and math take a body that starts with brace-bang and ends at the first unescaped bang-brace from that point. The body is not tokenized as DocUP.

If the first line after the opener is only spaces, tabs, or CR, that line is dropped. Trailing spaces and newlines are dropped. Empty content after that trim is a semantic error.

To put a bang-brace in the body, escape it:

  • backslash, bang, brace — stored as bang-brace
  • bang, backslash, brace — stored as bang-brace
  • two backslashes, bang, brace — stored as backslash, bang, brace

3.6 Attribute lists

Many blocks take a parenthesized list after the name:

text 
name(key: "value", flag: true, "positional")

A named field is an identifier, a colon, then a string or the identifiers true / false. A string "true" is also accepted where the generator compares against the text true.

A bare string is a positional argument. Entries may be separated by commas. An empty () is valid where the list is optional.

Which keys are read depends on the block. Unknown keys do not fail the parse. Heading attributes after the level are name/string pairs only; booleans are not accepted there.

3.7 Prose escapes

In paragraph-like text, a backslash before one of these characters emits that character and does not start syntax:

  • backslash brace-open — a literal open brace
  • backslash brace-close — a literal close brace
  • backslash bang — a literal bang
  • two backslashes — a literal backslash

Inside inline code, backslash-brace is unescaped to a brace and does not change brace depth. Inside inline math, backslash-brace is kept so KaTeX still sees it.

4. meta

Optional. At most one per document. If present it must contain title.[1]

meta.du
text 
meta {
  title: "Required when meta is present",
  lang: "en",
  theme: "textbook",
  author: "Name",
  version: "0.2.0",
  description: "One-line summary",
  keywords: "comma, separated",
  canonical: "https://example.com/page",
  image: "https://example.com/og.png",
  stylesheet: "extra.css"
}

Keys the generator uses:

Key Effect
title Document title and Open Graph / Twitter title. Required if meta exists.
lang lang on <html>. Default en.
theme Named page theme and the data-theme attribute. See section 4.1.
author, version <meta name> tags.
description description, og:description, twitter:description.
keywords <meta name="keywords">.
canonical canonical link and og:url.
image og:image and twitter:image. This is not the content image block.
stylesheet Extra <link rel="stylesheet"> in head. Separate from --style.

Values are strings. A second meta block is a parse error. Other keys are kept in the AST and ignored by the generator. fmt writes known keys in this order: title, author, version, theme, lang, description, keywords, canonical, image, stylesheet, then any other keys alphabetically.

4.1 Themes

meta field theme selects fonts, colors, and extra CSS. Matching is case-insensitive.

Name Also accepted Fonts
textbook latex, academic, book Literata, Cascadia Code
default any other string, including light and dark Google Sans Flex, Google Sans Code
sepia warm, editorial Merriweather, JetBrains Mono
nord arctic Inter, JetBrains Mono
solarized Fira Sans, Fira Code

textbook also changes tables (booktabs-style rules, no vertical borders) and callout titles.

The same string is written to data-theme on <html>.[2]

  • light — default theme, light palette locked.
  • dark — default theme, dark palette locked.
  • a named theme — that theme's light palette by default; the dark palette still follows prefers-color-scheme.
  • omitted — default theme, follows prefers-color-scheme.

docup new and docup init accept the five names in the table. Unknown values there fall back to textbook.

5. Blocks

5.1 h

Heading. Level is a number in parentheses and must be 1 through 6. The body is prose.

text 
h(1) { Title }
h(2, id: "install", class: "section") { Install }

Optional attributes after the level are name/string pairs. The generator writes id and class. Other keys are stored and not written.

If you omit id, the generator builds one from the heading text: ASCII letters and digits kept in lowercase, spaces / hyphens / underscores turned into a single hyphen, other characters dropped, trailing hyphens stripped. An empty result becomes section. Duplicate slugs get a numeric suffix.

5.2 p

A paragraph. Body is prose: text plus inline elements.

text 
p { One paragraph. Use another p block for the next one. }

5.3 hr

Horizontal rule. Empty body.

text 
hr {}

5.4 toc

Table of contents. Empty body. The generator fills it from every heading in the finished document, after includes are resolved. Headings are listed in source order with links to their ids. If there are no headings, the block emits nothing.

text 
toc {}

5.5 raw

Unescaped HTML. Header name raw, then a raw scope (section 3.5).

text 
raw

Follow that header with a raw scope. Nothing inside the scope is lexed as DocUP.

6. Inlines

Inlines appear in prose bodies: headings, paragraphs, callouts, table cells, footnote definitions, and the text parts of list items and quotes.

Brace forms: b, i, strike, code, m. Parenthesis forms: link, fn.

6.1 Emphasis

text 
p { b{bold} i{italic} strike{struck} }

These nest. Depth is capped at 64 and is shared with nested lists and quotes.[3]

Rendered: bold italic struck. Combined: bold italic.

6.2 Inline code

code{...} reads bytes until the matching closing brace. Nested braces are counted. There are no inlines inside it. Backslash-brace becomes a literal brace and does not change depth. HTML special characters in the body are escaped in output.

text 
p { Use code{list} as a top-level block. }

6.3 Links

text 
p { See link("https://example.com") { the site }. }

The URL is a string inside parentheses. The visible text is the brace body. An empty URL is a semantic error. Extra comma-separated string attributes after the URL are parsed and discarded.

Example: example.com.

6.4 Inline math and footnote refs

Inline math uses m{...} and is described in section 10.2. Footnote references use fn(id) and are described in section 14.

An identifier that looks like an inline but is not one of the names above is ordinary text.

7. Lists

A list contains item and task children only. Zero items is a semantic error.

text 
list {
  item { First }
  item { Second }
}

list(ordered: true) {
  item { Step one }
  item { Step two }
}

ordered: true emits <ol>. Anything else, including omitting the attribute, emits <ul>.

7.1 Tasks

text 
list {
  task(done: false) { Open work }
  task(done: true) { Finished work }
}

done is a boolean. Missing done is treated as false. The checkbox is rendered disabled.

  • Write the grammar down
  • Add a new block type

7.2 Nested lists

A list may appear inside an item. It must be the last child of that item.[4]

text 
list {
  item {
    Parent text
    list {
      item { Child }
      item { Other child }
    }
  }
  item { Sibling of the parent }
}
  • Block types
    • Prose: h, p, quote, callout
    • Structure: list, table, toc
    • Pass-through: raw, codeblock, math
  • Inline types: b, i, strike, code, m, link, fn

8. Quotes

A block quote. Body is prose and, optionally, one nested quote at the end.

text 
quote {
  Outer line.
  quote {
    Inner line.
  }
}

A quote is a block, not an inline. Consecutive text inside it becomes one paragraph in HTML.

The inner quote closes the outer body. Do not put text after it.

9. codeblock

Fenced source. After the attribute list, the body is a raw scope (section 3.5).

text 
codeblock(lang: "rust", file: "main.rs", line_numbers: true, highlight: "1,3-5")

Follow the attribute list with a raw scope. The live block in section 9 is the same construct.

Attributes:

Key Type Effect
lang string Language label, language-* class, and highlight grammar. Empty means no language class.
file string Label in the header.
line_numbers boolean Show line numbers. Default false.
highlight string Line numbers to mark. Comma-separated items, each a number or an inclusive range written start-hyphen-end.

Content empty after trim is a semantic error. The output header always includes a Copy button.

rust

9.1 Highlight languages

lang is normalized to a profile. Unknown names still get a generic highlighter (line comments with // or #, block comments, quoted strings). Aliases and extensions map to the same profile: rs is rust, py is python, c++ is cpp.

Profiles with keyword lists include:

  • Systems: rust, c, cpp, go, zig, odin, nim, d, assembly
  • Functional: haskell, ocaml, elixir, erlang, clojure, fsharp, lisp, scheme, elm, purescript, sml
  • JVM and similar: java, kotlin, scala, csharp, swift, dart, groovy, apex, vb
  • Scripting: python, ruby, php, perl, lua, r, julia, crystal
  • Web: javascript, typescript, html, xml, css, scss, json, yaml, toml, ini, graphql, markdown
  • Shell: bash, powershell, batch, dockerfile, makefile, cmake, terraform
  • Data and hardware: sql, solidity, vhdl, verilog, systemverilog
  • Classical: cobol, fortran, pascal, ada

Tokens are marked as keyword, type, string, comment, or number.

10. Math

Two forms. Both need KaTeX at runtime. The generator adds the KaTeX tags only if the document contains at least one math node.

10.1 Display

Header line is math, then a raw scope of LaTeX. Empty content is a semantic error. Output is wrapped as display math.

\[ \int_{0}^{1} x \, dx = \frac{1}{2} \]

10.2 Inline

m{...} is a raw brace body. No nested inlines inside it. Backslash-brace is kept for KaTeX. In inline code the same sequence is unescaped to a brace.

text 
p { The area is m{\frac{1}{2}}. }

The area is \(\frac{1}{2}\). Einstein: \(E = mc^2\).

11. Tables

A table is rows. A row is cells. A cell body is prose.

text 
table {
  row(header: true) {
    cell { Name }
    cell { Kind }
  }
  row {
    cell { code{p} }
    cell { block }
  }
  row {
    cell { code{b} }
    cell { inline }
  }
}

Rules checked after parse:

  • At least one row.
  • Each row has at least one cell.
  • Every row has the same number of cells.

row(header: true) emits <th> instead of <td>. Table-level attributes are parsed and ignored.

Live example, pulled in with include:

Token Spelling Used for
Ident letters, digits, underscore block names, attribute keys, true / false
String double-quoted paths, URLs, attribute values
Number digits heading level
RawScopeOpen brace-bang codeblock, raw, math

12. Images

No body. First argument is the source URL or path. Optional alt is a string. Other named attributes after that are parsed and ignored.

text 
image("images/banner.png", alt: "DocUP")

An empty source is a semantic error. In watch mode the server maps request paths onto files next to the root input. Relative paths in the compiled HTML are resolved by the browser against the HTML file.

The banner at the top of this page is that block.

13. Callouts

Admonition block. Body is prose.

text 
callout { Defaults to note. }
callout(type: "warning") { Check the heading level. }

type is a string. Matching is case-insensitive.

type Also accepted
note info
tip hint
warning caution
danger error

Any other string is a parse error. Omitted type is note.

Note
Semantic errors are reported with file, line, and column. The compiler prints the source line and a caret.
Tip
Put examples in codeblock raw scopes so the sample is not parsed as DocUP.
Warning
Heading levels outside 1 through 6 fail semantic analysis, not parsing. The tokens are valid; the values are not.
Danger
include cycles and missing include files fail before semantic analysis. The error is reported against the include statement.

14. Footnotes

A definition is a top-level block. A reference is an inline.

text 
p { See the rule.fn(required-title) }

footnote(id: "required-title") { Title is required when meta is present. }

The definition needs a non-empty id attribute. The body is prose.

The reference is fn(id) or a quoted string inside the parentheses. The identifier form allows letters, digits, underscore, and hyphen.

Checks:

  • Duplicate definition ids are a semantic error.
  • A reference whose id has no definition is a semantic error.
  • Definitions with no references still appear in the footnotes section.

Numbering follows first-reference order in the document after includes are merged. Definitions that were never referenced are appended after that list. Output ids are fn- plus the id, and fnref- plus the id.

This page uses four definitions. Earlier sections reference the first three.[5]

15. Includes

Splice another .du file into the current document. Two spellings:

text 
include "path/to/file.du"
include("path/to/file.du")

The path is relative to the file that contains the statement, not to the process working directory.

Resolution:

  1. Join the path to the parent file's directory.
  2. Canonicalize. Failure is an error on the include statement.
  3. Reject the path if it is already on the current include stack (cycle).
  4. Read, lex, parse the child.
  5. Resolve includes inside the child.
  6. Append the child's blocks to the parent. Child meta is discarded.[5]
  7. Pop the child from the stack so the same file may be included from a different branch.

An empty path is a semantic error if the statement survives until analysis. A missing file fails earlier, during resolution.

Watch mode adds every successfully resolved include to the watch set.

This document is one HTML file built from several .du files. index.du holds meta, the banner, the title, the toc, the includes, and the footnote definitions.

16. Semantic checks

Analysis runs on the document after includes are expanded. The first violation stops the build.

Check When it fires
meta title meta is present and has no title field
heading level level is not in 1..6
empty codeblock / raw / math trimmed content is empty
empty list no items
empty table no rows
empty row no cells
ragged table a row's cell count differs from the first row
image src source string is empty
link URL URL string is empty
include path path is empty or only whitespace
footnote id duplicate definition, or a reference with no definition

Parse errors are separate: unknown block names, missing braces, bad callout types, unclosed raw scopes, unclosed strings, unclosed comments, nesting past 64, text after a nested list or nested quote.

16.1 Diagnostics

Errors print the message, then path:line:col, then the source line and a caret. Line and column are 1-based. File errors use distinct text for not found and permission denied.

17.3 Limits

  • One meta block.
  • Include cycles are rejected.
  • Inline, list, and quote nesting share a cap of 64.
  • Nested list or quote must be the last child of its parent body.
  • No block inside a paragraph. A list inside a p body is plain text.
  • Child-file meta is not merged.
  • A raw scope ends at the first unescaped bang-brace.

17.4 Building these pages

The root file is index.du. From the docs directory:

text 
docup build index.du
docup build index.du -o index.html
docup watch index.du --port 8080
docup fmt index.du --check

Output defaults to index.html next to the input.

Heading levels

Levels 1 through 6 are valid. This section is level 4.

Level 6

Level 6. Compiler version 0.2.0.

  1. If a document contains a meta block, that block must include a title field. A document with no meta block is valid; the generated page title then defaults to "DocUP Document". ↩
  2. The generator writes the raw theme string onto data-theme. Palette lock to light or dark only happens when that string is exactly light or dark. Named themes such as textbook still follow prefers-color-scheme for the dark variant unless you also force light or dark. ↩
  3. Inlines, nested lists, and nested quotes share one depth counter. The cap is 64 for the combination, not 64 of each. ↩
  4. After a nested list is parsed inside an item, the item must close. Text after that nested list is a parse error. The same rule applies to a nested quote inside a quote. ↩
  5. An included file may contain its own meta block. The compiler parses it, then drops it. Only the included file's blocks are spliced into the parent. ↩
